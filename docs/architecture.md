# 系统架构与数据流

## 总体流程

```text
原始收藏（只读）
  │ 人工筛选 / 010 复制
  ▼
工作副本
  │ 020 只读扫描
  ▼
扫描批次 ──030──► 重复检测报告
  │
  ├─050──► 首轮分类建议
  │          │
  │         051 / 052 模型复核
  │          ▼
  │       权威一级分类结果
  │          │
  │         060 生成计划 ──人工批准──► 一级分类副本
  │          │
  └─────────070 同人作品分类与特殊目录辅助分组
             │
             080 生成计划 ──人工批准──► 选择性分组副本
```

扫描、分类与计划是可审计产物，不是文件整理本身。只有批准执行步骤可以复制或移动工作副本中的文件。

## 身份与批次模型

- 一个物理文件在扫描索引中对应一个[文件记录](../CONTEXT.md)。
- 多个文件记录可以共享同一[唯一内容](../CONTEXT.md)。模型阶段按唯一内容减少重复请求，再把决定映射回全部文件记录。
- `reports/` 下的每次运行使用独立批次目录，历史批次不被覆盖。模型分类、复核、二次分类和整理计划会按各自安全要求记录来源哈希；030 重复检测只记录来源索引路径，不记录索引哈希。
- “最新目录”只适合便利性发现。可复现操作和当前状态应明确写出批次路径与哈希。

## 阶段与脚本

| 阶段 | 脚本 | 主要输入 | 主要输出 | 对角色卡文件的影响 |
|---|---|---|---|---|
| 010 收集 | `src/010-collect-character-cards.ps1` | 脚本内配置的人工来源目录 | `data/未分类角色卡/`、`reports/collection/` | 复制到工作副本；不改来源 |
| 020 扫描 | `src/020-scan-character-cards.mjs` | 工作副本中的 PNG/JSON | `reports/scans/<批次>/` | 仅读取角色卡；写报告 |
| 030 去重审计 | `src/030-detect-duplicates.mjs` | 扫描 `index.jsonl` | `reports/duplicates/<批次>/` | 不读取或修改原文件；写报告 |
| 050 分类 | `src/050-classify-character-cards.mjs` | 扫描索引、`分类标准.md` | `reports/classifications/<批次>/` | 不改角色卡；真实运行会调用外部模型 |
| 051 复核 | `src/051-classify-character-cards.mjs` | 完整 050 结果及其绑定输入 | `reports/classification-reviews/<批次>/` | 不改角色卡；真实运行会调用外部模型 |
| 052 再复核 | `src/052-classify-character-cards.mjs` | 完整 051 结果及其绑定输入 | `reports/classification-reviews-052/<批次>/` | 不改角色卡；真实运行会调用外部模型 |
| 060 一级整理 | `src/060-organize-character-cards.mjs` | 完整分类结果 | `reports/organization-plans/<批次>/`；批准后写一级分类副本 | 预览只写计划；执行可复制或移动 |
| 070 选择性细分 | `src/070-refine-character-cards.mjs` | 完整 052 结果、扫描索引 | `reports/refinements/<批次>/` | 预检只建批次；真实运行仅为“同人”调用外部模型，特殊目录在本地分组 |
| 080 选择性整理 | `src/080-organize-refined-character-cards.mjs` | 当前范围的完整 070 结果、一级分类副本 | `reports/refinement-plans/<批次>/`；批准后写选择性分组副本 | 预览只写计划；执行只允许复制 |

## 分类与整理边界

050、051、052 产生 `classify`、`exclude` 或 `review`。060 不会删除排除或未决项目：它把三种决定映射到普通类别、`排除`、`未分类`，并把规则外的历史类别收拢到 `标准外`。这些目录是一级处置结果，不会改变原有模型决定。

070 的当前范围是 `fanwork-ip-and-special-groups-v1`。只有文件数严格大于 100 的`同人`一级类别会调用模型，并按作品或系列 IP 增加一层[二次分类](../CONTEXT.md)；`排除`、`未分类`和`标准外`超过同一阈值时，仅依据已有原因或原类别产生本地确定性的[整理辅助分组](../CONTEXT.md)。其他普通一级类别无论数量多少都保持扁平，不调用模型，也不生成二级目录。所有细分都只增加一层，不递归拆分。

080 同时校验批次范围和每条结果的父类。缺少当前范围标识的旧 070 批次会被拒绝，普通一级类别携带二级目录也会被拒绝，避免旧版“所有超阈值类别都细分”的结果进入新目录树。

## 共享运行能力

各阶段脚本保留独立命令入口，并把可复用行为集中在 `src/lib/`：CLI 参数解析、报告读写、角色卡解析、模型批次与重试、分类复核流程，以及整理计划执行。脚本被其他模块导入时不会自行运行；直接从命令行调用时仍使用原有参数和产物格式。

050、051、052 和 070 的同人作品分类共用模型批次的遗漏项重试与失败拆分规则。051、052 共用完整的复核生命周期，但分别保留自己的目标筛选、提示词版本、历史字段和汇总字段。060、080 共用批准、路径边界、哈希验证、排他复制与失败清理规则，同时保留 060 可移动、080 仅复制的阶段差异。

## 完整性与审批

- 分类续跑绑定模型、提示词、输入文件和分类规则哈希；不一致时拒绝继续。
- 060 和 080 的计划包含来源、目标和 SHA-256，并生成默认未批准的 `approval.json`。
- 执行前重新核对计划哈希、批准文件和来源文件哈希；目标存在时拒绝覆盖。
- 060 的 `move` 实现为复制、校验、再删除来源。080 固定为 `copy`。
- 执行结果写入新的 `execution-*.jsonl/.csv` 和 `execution-summary-*.json`，不会回写原计划的 `summary.json`。

## 路径兼容

当前工作目录使用 `data/未分类角色卡/` 和 `data/已分类角色卡/`。部分历史批次保存了旧路径 `data/角色卡/未分类` 与 `data/角色卡/已分类`；相关分类与整理脚本通过 `src/lib/data-paths.mjs` 将旧路径映射到当前布局。当前文档和新命令使用现行相对路径，历史快照保留当时的绝对路径。
