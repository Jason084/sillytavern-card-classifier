# 架构与数据流

[English](./architecture.md)

## 流水线

```text
只读原始收藏
  └─010 复制──> 本地工作副本
       └─020 扫描──> 不可变扫描批次
            ├─030──> 重复审计
            └─050──> 首轮模型分类
                  └─051/052──> 两轮复核
                        └─060 计划──批准──> 一级分类副本
                              └─070 选择性细分
                                    └─080 计划──批准──> 细分副本
                                          └─090 同人 IP 归并建议
                                                └─100 计划──批准──> 归并副本
```

报告和分类结论只是审计证据，不等于文件操作。只有 060、080 和 100 的已批准执行模式会写入整理后的角色卡副本。

## 阶段契约

| 阶段 | 主要输入 | 主要输出 | 对角色卡文件的影响 |
|---|---|---|---|
| 010 收集 | 用户显式提供的来源目录 | 工作副本与 CSV 日志 | 只复制，来源保持不变 |
| 020 扫描 | 工作副本中的 PNG/JSON | `reports/scans/<批次>/` | 只读 |
| 030 重复审计 | 扫描索引 | `reports/duplicates/<批次>/` | 索引后不再访问角色卡 |
| 050 分类 | 扫描索引与 `分类标准.md` | 分类批次 | 向配置的模型发送裁剪字段 |
| 051/052 复核 | 前一完整批次与分类政策 | 合并后的复核批次 | 只发送尚未确定的目标卡 |
| 060 整理 | 完整分类批次 | 与批准绑定的计划 | 预览只写报告；执行可复制或明确移动 |
| 070 细分 | 完整分类批次与扫描批次 | 选择性细分批次 | 对选中的同人调用模型，特殊组走确定性规则 |
| 080 细分整理 | 完整 070 批次与一级副本 | 与批准绑定的计划 | 只允许复制 |
| 090 归并建议 | 完整 070 与已执行 080 的证据 | 可人工审核的 IP 映射 | 只写报告 |
| 100 归并整理 | 已批准 090 映射与细分副本 | 完整复制计划 | 只允许复制 |

## 身份与完整性

一次扫描中的一个物理文件对应一个文件记录。多个文件记录可以共享同一逻辑内容哈希，因此模型调用可以按内容去重，同时保留逐路径追踪能力。每次运行写入独立批次目录，不覆盖旧批次。

模型批次绑定输入哈希、提示词版本、端点配置和政策哈希。整理计划绑定来源路径、目标路径、操作类型和 SHA-256。执行前会重新校验批准文件、计划哈希、来源哈希和目标边界。

## 模型数据边界

050、051、052 和 070 通过环境变量配置 OpenAI 兼容的 `/chat/completions` 端点。端点会收到经过裁剪的名称、标签、描述字段、开场白、提示词和角色书文本。API 密钥与授权头不会写入报告。

流水线把政策文本、角色卡字段和目录名都视为不可信数据。模型必须返回受约束的 JSON；遗漏或格式错误只会在显式重试次数和请求预算内重试。

## 共享模块

`src/lib/` 集中 CLI 解析、角色卡解析与哈希、JSONL I/O、批次元数据、模型请求与预算、细分规则和已批准计划执行。所有阶段都导出 `main`，被导入时不会自动运行。
