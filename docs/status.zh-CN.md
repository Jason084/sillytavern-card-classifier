# 项目状态

[English](./status.md)

最后核实日期：2026-09-14。

本页是软件当前可验证的能力、成熟度和已知限制的唯一权威来源。历史阶段当时的结论见[历史快照](./history/)，维护者的私人验证证据单独记录在[验证案例](./validation-case-study.zh-CN.md)中。

`v0.1.0` 仍是首个公开预览基线。

## 当前能力

- 仓库包含经过验证的 010–110 流程：收集、扫描、重复检测、一级分类、选择性同人细分、IP 归并和分类标签写入。
- 整理和标签写入阶段使用绑定批准与哈希校验的计划，并写入副本；原始收藏不在写入路径中。
- 模型请求使用服务商中立的共享配置。本地服务可以使用 HTTP；远程端点必须使用 HTTPS，并且必须显式授权。
- 支持平台契约为 Windows 10 或更高版本、PowerShell 7，以及 Node.js 22 或 24 LTS。Linux 和 macOS 可能可以运行部分 Node.js 流程，但不属于 v0.1 支持契约。
- 仓库的 `npm run check` 覆盖语法检查、自动化测试、Markdown 链接、公开内容和分类政策译文检查。2026-09-14 本地核验通过全部 39 项测试及所有检查阶段。

## 已知限制

- 模型分类质量取决于所选端点，必须人工复核。
- 内置中文分类政策服务于特定工作流，使用前应自行审核。
- 060 为可丢弃工作副本保留显式 `move` 选项；后续整理阶段只允许复制。
- v0.1 不承诺兼容公开流程创建以前的私人批次。
- 110 支持当前解析器可识别的 PNG `tEXt` 元数据和 JSON 角色卡。异常元数据必须修复，或经显式批准作为原样复制兼容例外。

## 下一安全步骤

1. 查看[验证案例](./validation-case-study.zh-CN.md)中的维护者验证结论和追溯引用。
2. 在把输出视为质量已批准前，继续人工抽检同人细分目录、分类标签、排除目录和待复核记录。
3. 如果要执行 070 v2，应新建并完成独立模型批次。分类标准哈希或提示词版本变化后不得续跑旧批次。
4. 在 SillyTavern 中确认带标签副本前，继续保留既有复制结果。

## 阻塞与待人工决定

- 当前复制和哈希完整性流程没有技术阻塞。剩余工作是人工质量抽检，以及是否运行 070 v2 批次的产品决定。
- 模型端点可能把内容过滤响应包装成 HTTP 200；已完成批次通过记录中的元数据降级处理了这类响应。这被视为上游行为，不作为客户端待修复事项。
- 历史待复核和排除决定仍需人工质量复核；复制成功不代表分类决定一定正确。

具体命令和安全警告见[运行手册](./runbook.zh-CN.md)。本状态页不对当前 PowerShell 进程是否存在模型凭据作断言。
